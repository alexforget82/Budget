MON BUDGET 3.3 — INSTALLATION ET MISE À JOUR SUR MAC

Node.js 22.13 ou plus est requis. Node.js 24 LTS est recommandé.
Aucune commande npm install n’est nécessaire.

MISE À JOUR RECOMMANDÉE — NOUVEAU DOSSIER
1. Arrêtez l’ancienne application dans Terminal avec Control + C.
2. Faites une copie INTÉGRALE de votre dossier actuel, y compris data
   (budget.sqlite et ses éventuels fichiers -wal et -shm).
3. Décompressez le nouveau ZIP GitHub dans un NOUVEAU dossier distinct.
   Vous pouvez renommer ce dossier Mon-Budget-3.
4. COPIEZ le dossier data de votre ancienne application dans ce nouveau
   dossier, au même niveau que server.js. Ne déplacez pas l’original.
   Le ZIP ne contient aucun dossier data; il n’y a rien à remplacer.
5. Gardez tous les nouveaux fichiers applicatifs ensemble : server.js,
   budget-features.js, index.html, app.css, app.js, features.js, planner.js,
   transactions.js, forecast-engine.js, forecast-ui.js, planning-actions.js,
   planning-workflow.js, private-access.js et package.json.
   IMPORTANT : contrairement à la mise à jour visuelle précédente, remplacer
   seulement trois fichiers ne suffit plus.
6. Ouvrez Lancer Mon Budget.command dans ce NOUVEAU dossier, ou lancez
   npm start depuis Terminal dans ce dossier.
   Astuce : tapez cd suivi d’un espace, glissez le nouveau dossier depuis
   le Finder dans Terminal, puis appuyez sur Entrée. Tapez ensuite npm start.
7. Dans Safari, ouvrez http://127.0.0.1:3030 et rechargez avec Cmd + Option + R.
8. Vérifiez vos soldes avant de continuer. Gardez l’ancien dossier et sa
   copie de sauvegarde intacts pour pouvoir revenir en arrière.

La migration ajoute des colonnes et tables. Elle conserve les opérations,
les comptes, les enveloppes et les règles existants. Une copie SQLite
cohérente est créée avant les ajouts v3 dans data/backups/budget-before-v3.sqlite.
Une copie manuelle complète avant mise à jour reste importante.
Vérifiez vos soldes et vos enveloppes après la mise à jour.

LANCEMENT PAR DOUBLE-CLIC
Vous pouvez ensuite ouvrir Lancer Mon Budget.command depuis le Finder.
Ce lanceur ouvre votre navigateur et garde une fenêtre Terminal ouverte.
Fermer le serveur avec Control + C quand vous avez terminé.
Il ne s’agit pas d’une application .app autonome : Node.js reste nécessaire.
Si macOS refuse l’ouverture, essayez clic droit > Ouvrir.
Si les permissions du fichier ne permettent pas de le lancer, depuis
Terminal dans le dossier de l’application :
  chmod +x "Lancer Mon Budget.command"
Ne lancez pas deux serveurs sur la même base.

NOUVELLE INSTALLATION
Gardez tous les fichiers du dossier Budget-main ensemble.
Lancez npm start depuis ce dossier ou ouvrez le lanceur .command.
Une base vide est créée dans data dans le dossier de lancement.

NOUVEAUTÉS (3.2)
- Planifier > Prévu / Réel > À confirmer : traiter les opérations en retard,
  celles d'aujourd'hui et les prochaines échéances.
- Confirmer le réel : montant et date réellement passés. Si l'opération
  est déjà enregistrée, choisir Déjà saisie pour l'associer sans redébiter
  le compte. Les virements sont enregistrés comme un seul virement.
- Pour plusieurs achats d'enveloppe, décocher Aucun autre achat prévu
  pour cette période. Le reste du budget reste projeté.
- Modifier le prévu, Reporter ou Annuler n'affecte qu'une occurrence,
  sans modifier les soldes bancaires réels.
- Historique complet : retrouver les opérations traitées et annulées.
- Planifier > Prévision : choisir une date et consulter Pourquoi ce solde ?
  pour voir les revenus, factures, enveloppes, virements et réserves.
  Chaque groupe peut être développé pour consulter les mouvements.
- Aucune réserve automatique pour les cartes : ce fonctionnement reste
  inchangé. Seuls les remboursements prévus ou réels sont pris en compte.
- Copie SQLite avant migration : data/backups/
  budget-before-planning-actions.sqlite. Les exports JSON v3/v3.1 restent
  restaurables. Le suivi utilise les règles actuelles, sans reconstituer
  les prévisions antérieures à son activation.

PRÉVISION ET RÉEL (3.1)
- Planifier > Prévision : choisir une date, puis lire le solde bancaire
  projeté, les réserves et le disponible. La courbe est au choix.
- Enveloppes : choisir Dépense prévue ou Réserve seulement, puis le compte,
  le budget, la fréquence et la première date. Les dépenses prévues sont
  déduites aux dates et apparaissent au calendrier.
- Planifier > Prévu / Réel : les achats affectés à une enveloppe remplacent
  le budget de leur période. Cliquez Encore des achats si vous prévoyez
  d'autres achats, puis Terminer la période quand tout est passé.
- Associer un réel permet de rapprocher une facture au montant différent.
- Aucune réserve automatique pour les cartes : seuls les virements de
  remboursement prévus ou enregistrés réduisent le disponible.
- Vérifiez les avertissements (enveloppes à planifier, comptes à choisir,
  mouvements passés à confirmer).
- Le suivi commence à la mise à jour. Les prévisions passées ne sont pas
  reconstituées. Une copie avant migration est créée dans data/backups/
  budget-before-planning-v4.sqlite. Les anciens exports JSON v3 restent
  restaurables.

LES AUTRES FONCTIONS
- Transaction : choisir Dépense ou Revenu, puis un montant positif.
- Bilan mensuel : catégories, revenus, dépenses et plafonds mensuels.
- Import CSV : fichier UTF-8, aperçu, sélection et doublons possibles.
  Le mode historique conserve les soldes actuels. Ne réappliquez pas
  aux soldes des opérations qui y sont déjà incluses.
  Les virements entre vos comptes et paiements de carte doivent être
  saisis comme virements; décochez-les dans l’aperçu CSV.
- Comptes : comparaison au solde bancaire et correction avec une note.
- Objectifs : suivi manuel distinct des enveloppes, sans déplacer d’argent.
- Sauvegardes : export JSON complet et restauration après vérification.
  Une copie du budget précédent est conservée juste avant la restauration.
